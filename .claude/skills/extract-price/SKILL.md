# extract-price

Извлечь цену товара с одной страницы по URL и вернуть структурированные данные.

## Что на входе и на выходе

**Вход:** один URL страницы товара, например `https://7745.by/product/0838728`.

**Выход:** ровно один JSON-объект, без пояснений вокруг него:

```json
{"regular_price": 1349.0, "sale_price": 1199.99, "has_credit": true}
```

| Поле | Тип | Значение |
|---|---|---|
| `regular_price` | number | Обычная цена в BYN с копейками. Если скидки нет — это единственная цена на странице |
| `sale_price` | number \| null | Цена по скидке. `null`, если скидки нет |
| `has_credit` | boolean | `true`, если на странице предлагают рассрочку или кредит |

Инварианты, которые обязаны выполняться:

- `regular_price` — всегда заполнена (это цена «до скидки», а не итоговая к оплате);
- если `sale_price` не `null`, то `sale_price < regular_price`;
- цены — числа, не строки: `1349.0`, а не `"1 349,00 р."`;
- копейки сохраняются: `289.5` означает 289 руб. 50 коп.

## Как действовать

1. Запустить скрипт — он делает всю работу:

   ```bash
   python3 .claude/skills/extract-price/scripts/extract_price.py "<URL>"
   ```

   Зависимостей нет, только стандартная библиотека Python 3. Флаг `--debug`
   печатает в stderr, из какого источника взята каждая цена, — с него и начинать
   разбор, если результат выглядит странно.

2. Проверить результат на здравый смысл, прежде чем отдавать пользователю:
   - главный признак ошибки — не сама величина, а **соотношение**: если найденная
     цена в 2–24 раза меньше другой цены на странице или стоит рядом со «/мес»,
     «в месяц», «×12», это платёж по рассрочке, а не цена товара;
   - совсем мелкие значения (единицы рублей, вроде `3.0`) для насоса нереальны —
     почти наверняка подхватился процент скидки, обрывок числа или платёж за
     месяц. А вот `99.99` подозрительным считать не надо: дешёвые вибрационные
     насосы столько и стоят;
   - если `regular_price` равна `null`, скрипт цену не нашёл (код возврата 2).

3. Если скрипт не справился — открыть страницу через WebFetch и найти цену
   глазами, затем собрать объект вручную. Признаки в `references/price-formats.md`:
   как выглядят цены в BYN, по каким словам определяется рассрочка, какие блоки
   страницы нужно игнорировать.

4. Отдать JSON-объект. Если пришлось что-то домысливать (например, на странице
   две цены без явной пометки «старая»), сказать об этом одной строкой после
   объекта.

## Чего не делать

- Не считать ценой товара платёж за месяц рассрочки («от 99,99 р./мес»).
- Не брать цены из блоков «похожие товары», «с этим покупают», «вы смотрели» —
  это цены других товаров.
- Не ставить `has_credit: true` только потому, что слово «Рассрочка» есть в меню
  или подвале сайта: такая ссылка есть на всех страницах магазина и о конкретном
  товаре ничего не говорит.
- Не выдумывать цену, если страница недоступна. Сказать, что страницу не удалось
  открыть, и показать причину.

## Проверка скилла

Офлайн-тесты на фикстурах, сеть не нужна:

```bash
python3 .claude/skills/extract-price/tests/test_extract_price.py
```

Три случая: JSON-LD со скидкой, цена во встроенном JS-состоянии, микроразметка
без скидки. Все три должны быть `OK`.
