# Хранение прогонов: репозиторий tracker-data

Каждый прогон tracker уезжает в отдельный репозиторий с историей цен.

- **Репозиторий:** `VitaliShaklach/tracker-data` (private), ветка `main`.
- **Схема:** один прогон — один файл. Имя файла — дата прогона: `YYYY-MM-DD.json`.
- **Расположение:** корень репозитория, без подпапок.
- **Содержимое:** таблица прогона в JSON — то, что печатает
  `run_tracker.py --format json`.

## Формат файла

```json
{
  "date": "2026-08-22",
  "started_at": "2026-08-22 09:14 UTC",
  "total": 7,
  "ok": 7,
  "failed": 0,
  "rows": [
    {
      "url": "https://catalog.onliner.by/pump/jileks/6550prof",
      "regular_price": 1349.0,
      "sale_price": 1199.99,
      "has_credit": true,
      "status": "ok",
      "note": ""
    }
  ]
}
```

| Поле | Что значит |
|---|---|
| `date` | дата прогона, совпадает с именем файла |
| `started_at` | момент запуска, UTC |
| `total` / `ok` / `failed` | всего товаров / с ценой / без цены |
| `rows` | строки таблицы, порядок как в `references/urls.txt` |
| `rows[].url` | страница товара |
| `rows[].regular_price` | обычная цена BYN, `null` если не получена |
| `rows[].sale_price` | цена по скидке или `null` |
| `rows[].has_credit` | признак рассрочки, `null` если строка не заполнена |
| `rows[].status` | `ok`, `no_price`, `fetch_failed`, `error` |
| `rows[].note` | причина, если `status` не `ok` |

Строка остаётся в файле даже без цены — прогон должен показывать, что товар
проверяли и что помешало. Пустые значения — `null`, не `0` и не строка.

## Как коммитить: GitHub MCP

Инструмент `mcp__github__create_or_update_file`:

| Параметр | Значение |
|---|---|
| `owner` | `VitaliShaklach` |
| `repo` | `tracker-data` |
| `branch` | `main` |
| `path` | `2026-08-22.json` — только дата, файл лежит в корне |
| `content` | JSON-текст как есть, без base64 |
| `message` | `Прогон 2026-08-22: 7/7 с ценой` |
| `sha` | **обязателен**, если файл за эту дату уже есть |

Порядок:

0. Убедиться, что `tracker-data` вообще доступен сессии. В сессии выбирают один
   репозиторий — обычно `hexlet-vibecoding`, где лежат скиллы, — и тогда вызовы
   GitHub MCP к `tracker-data` отвергаются как «вне scope». Подключить его:
   `mcp__Claude_Code_Remote__add_repo` с `owner: VitaliShaklach`,
   `repo: tracker-data`, `access: push`. Пользователь подтвердит подключение.
   Проверить, что репозиторий уже подключён, — `mcp__Claude_Code_Remote__list_repos`.

1. `mcp__github__get_file_contents` с тем же `path` — проверить, был ли прогон
   за эту дату.
2. Файла нет — вызвать `create_or_update_file` без `sha`.
3. Файл есть — это повторный прогон за тот же день: взять `sha` из ответа
   шага 1 и передать его, файл перезапишется. Второй файл на ту же дату не
   заводить, суффиксы вроде `-2` к имени не приписывать.

Если MCP-инструменты GitHub в сессии недоступны, а репозиторий склонирован
локально — записать файл и запушить обычным git. Схему хранения это не меняет.

## Чего не делать

- Не раскладывать прогоны по подпапкам с годами и месяцами: файлы лежат в корне.
- Не дописывать новый прогон в чужой файл и не вести один общий `history.json`.
- Не коммитить markdown-таблицу вместо JSON: markdown — для показа человеку,
  в tracker-data едет `--format json`.
- Не коммитить прогон, в котором не заполнена ни одна строка, не сказав об этом
  пользователю: сначала показать таблицу и причину, потом спросить.
